PNEUMO-FLUOR TOOLKIT (PFT)
================================================================================
Document version: 2026-08-02

PURPOSE
--------------------------------------------------------------------------------
This document identifies the responsibility of the current command-line scripts
and reusable core modules in the Pneumo-Fluor Toolkit. U can skip it, but it says what each function is doing 

ARCHITECTURE RULE
--------------------------------------------------------------------------------
1. User-facing commands are stored under:

   scripts/

2. Reusable implementation code is stored under:

   src/PFT/core_prog_parts/

3. Scripts import core code with package imports such as:

   from PFT.core_prog_parts.io import load_czi

4. The repository's src directory must be on the Python import path. The current
   scripts locate the repository from their own file location and add <root>/src
   when they are executed directly.


ENVIRONMENT RULE
--------------------------------------------------------------------------------
PFT uses three isolated environments because the supported segmentation
frameworks have different tested dependency stacks.

1. pft
   Main project environment. Cellpose 3 is installed as a normal dependency
   through pyproject.toml. This environment is responsible for the core
   microscopy pipeline, Cellpose, statistics, visualization, and optional U-Net.

2. pft_stardist
   Dedicated TensorFlow 2.10.1 and StarDist 0.9.2 environment.

3. pft_omni
   Dedicated Omnipose 1.1.4, CUDA-enabled PyTorch, and CUDA NVRTC environment.

The specialized environments install the local PFT package in editable mode
with --no-deps after their tested framework packages have been installed. This
prevents the main Cellpose dependency set from replacing the specialized pins.

Complete commands are maintained in PFT_environment_setup.txt.


LABELS
--------------------------------------------------------------------------------
[PRIMARY] Main supported workflow entry point.
[RUN]     User-facing terminal command or analysis utility.
[CORE]    Reusable processing implementation imported by scripts.
[SUPPORT] Shared paths, I/O, plotting, metadata, or conversion utilities.
[COMPAT]  Compatibility module retained for older imports.
[PACKAGE] Python package marker.
[SPECIAL] Specialized diagnostic, comparison, or thesis-output script.


A. PROJECT CONFIGURATION AND IMPORT VALIDATION
================================================================================

pyproject.toml
  [SUPPORT] Defines the PFT package, Python 3.10 requirement, standard pipeline
  dependencies, and Cellpose 3 as the primary segmentation dependency. It also
  records optional U-Net, Noise2Void, StarDist, Omnipose, BM3D, YOLO, napari,
  and development dependency groups. StarDist and Omnipose are still installed
  in isolated environments according to PFT_environment_setup.txt.


PFT_environment_setup.txt
  [PRIMARY] Reproducible PowerShell instructions for creating the pft,
  pft_stardist, and pft_omni environments. Documents tested package versions,
  CUDA requirements, direct-interpreter execution, environment validation,
  activation, switching, PyCharm interpreter selection, and environment export.

PFT_responsibilities.txt
  [PRIMARY] This file. Maps the user-facing scripts, reusable core modules,
  environment responsibilities, and principal output locations.

scripts/check_project_imports.py
  [PRIMARY] Checks that scripts/ and src/PFT/core_prog_parts/ belong to the same
  repository root. Indexes local PFT modules and verifies that local module and
  imported-symbol references exist. Writes results/import_check_report.txt.
  This check validates local source structure, not installation of third-party
  packages such as NumPy, TensorFlow, Cellpose, or napari.

scripts/__init__.py
  [PACKAGE] Marks scripts as an importable command-wrapper package.

src/PFT/core_prog_parts/__init__.py
  [PACKAGE] Marks the reusable core-processing package.

src/PFT/core_prog_parts/common_paths.py
  [SUPPORT] Central path utilities for finding the project root, creating output
  directories, normalizing dataset names, and resolving standard results/img
  and results/filters locations.


B. RAW-DATA DISCOVERY, CZI IMPORT, OME-ZARR CREATION, AND VALIDATION
================================================================================

PRIMARY WORKFLOW
--------------------------------------------------------------------------------
Raw CZI data
  -> scripts/denoising/process_czi.py
  -> data_discovery.py + io.py
  -> save.py + omezarr_utils.py
  -> omezarr_validation.py
  -> results/img/<dataset>/<sample>/

scripts/denoising/process_czi.py
  [PRIMARY] Main CZI-import command. Processes 2d_time, 2d_wga_dapi, 3d, or all
  datasets. Resolves raw-data folders, discovers CZI files recursively, loads
  pixels and metadata, creates compact TIFF/PNG exports, writes OME-Zarr, runs
  exact validation, and writes dataset/global summaries. Supports one-file,
  one-dataset, and all-dataset operation.

scripts/denoising/validate_omezarr.py
  [PRIMARY] Revalidates one or all existing *.ome.zarr stores against original
  CZI files. With no target, scans results/img. Keeps detailed checks in each
  sample's ome_zarr_validation.txt and creates compact dataset-level and global
  summary files. Can search a replacement raw-data root when source paths moved.

src/PFT/core_prog_parts/data_discovery.py
  [CORE] Resolves raw-data directories without assuming a fixed drive letter.
  Recognizes accepted dataset-folder aliases, searches parent folders, supports
  graphical/terminal selection, detects CZI content, and groups 3D CZI files by
  relative experiment directory.

src/PFT/core_prog_parts/io.py
  [CORE] Reads Zeiss CZI files. Loads the pixel array, reads CZI header axes and
  shape, extracts XML, physical sampling, channel names, channel settings,
  microscope, objective, detector, SIM, and acquisition information, and stores
  these values in the CziMeta dataclass.

src/PFT/core_prog_parts/save.py
  [CORE] Writes per-sample outputs below results/img. For 2D data it writes
  metadata.txt, metadata.xml, image_norm16.tif, image_norm16_rgb.tif,
  preview_raw.png, preview_norm.png, image.ome.zarr, and
  ome_zarr_validation.txt. It intentionally does not create duplicate raw TIFF
  files because lossless, non-normalized source pixels are retained in OME-Zarr
  level 0. For 3D it writes metadata reports and validated multiscale OME-Zarr.

src/PFT/core_prog_parts/omezarr_utils.py
  [CORE] Writes OME-NGFF OME-Zarr data. Determines canonical axes, preserves
  exact non-normalized level-0 pixels, stores physical scales and complete CZI
  metadata, writes channel information, and optionally creates lateral XY
  multiscale pyramid levels for 3D data.

src/PFT/core_prog_parts/omezarr_validation.py
  [CORE] Performs exact OME-Zarr validation. Compares axes, shape, dtype, every
  level-0 pixel, SHA-256 digest, channel names, physical scales, pyramid layout,
  XML sidecar content, and all CziMeta fields. Writes detailed per-image reports,
  compact per-dataset summaries, and a global results/img summary.

src/PFT/core_prog_parts/decoder_omezar.py
  [CORE] Reads and standardizes existing OME-Zarr arrays. Handles axis
  normalization, CZYX conversion, selected slices, complete 3D volume loading,
  N2V stack preparation, metadata extraction, and PSF-generator configuration
  parsing used by diagnostic and restoration scripts.

scripts/denoising/damp_meta.py
  [SPECIAL] Reads selected CZI files and dumps header, array-shape, and XML-based
  metadata for inspection. Useful when testing metadata parsing or diagnosing
  unusual CZI dimensions before conversion.

scripts/denoising/sanity_2d.py
  [RUN] Opens a 2D OME-Zarr level, selects a representative plane, splits
  channels, normalizes display data, and performs a quick visual sanity check.
  It is a visual inspection tool, not the exact preservation validator.

scripts/denoising/sanity_3d.py
  [RUN] Inspects 3D OME-Zarr hierarchy, multiscale metadata, axes, channel count,
  and selected content. Used for structural and visual checks after conversion.

scripts/denoising/from_ome_to_tiff.py
  [SPECIAL] Exports grouped, normalized, colored TIFF representations from
  denoised OME-Zarr volumes. It is a downstream export utility and does not
  replace the original CZI-to-OME-Zarr import workflow.

scripts/segmentation/collect_training_omezarr.py
  [SPECIAL] Collects image.ome.zarr stores from results/img and transfers them
  into results/training_files for segmentation training. Current behavior uses
  shutil.move, so source OME-Zarr stores are removed from results/img unless the
  script is changed to copy. Use deliberately and only after validation.


C. SHARED IMAGE, VISUALIZATION, AND PLOTTING UTILITIES
================================================================================

src/PFT/core_prog_parts/image_utils.py
  [SUPPORT] Numeric image helpers for percentile/min-max normalization, dtype
  conversion, display-plane extraction, shared raw scaling, and construction of
  time-series and WGA-DAPI RGB composites.

src/PFT/core_prog_parts/visualization.py
  [SUPPORT] Shared visualization functions for 2D/3D processing. Creates channel
  composites, microscopy previews, FFT displays, scale bars, comparison panels,
  TIFF figures, U-Net overlays, and single-channel outputs. Preview functions
  call normalize01_percentile with the currently supported p_lo/p_hi arguments.

src/PFT/core_prog_parts/visualize_2d.py
  [COMPAT] Re-exports functions from visualization.py for older imports. New code
  should import PFT.core_prog_parts.visualization directly.

src/PFT/core_prog_parts/plot_utils.py
  [SUPPORT] Common publication-figure helpers for scale bars, axis styling,
  figure finalization, and side-by-side image export.


D. DENOISING, FILTERING, PSF GENERATION, AND DECONVOLUTION
================================================================================

D1. USER-FACING DENOISING AND DIAGNOSTIC SCRIPTS
--------------------------------------------------------------------------------

scripts/denoising/__init__.py
  [PACKAGE] Marks the denoising command package.

scripts/denoising/check_2d.py
  [RUN] Computes 2D image-quality and noise diagnostics for time-series and
  WGA-DAPI OME-Zarr data, including robust difference-based noise estimates and
  channel/image measurements. Produces analysis reports rather than denoised
  images.

scripts/denoising/check_3d.py
  [RUN] Computes 3D image and metadata diagnostics, including noise, correlation,
  intensity-trend, sampling, and volume consistency checks.

scripts/denoising/noise_checks.py
  [RUN] General noise-pattern assessment using neighbor correlations, row/column
  correlation, FFT peak scores, and saved image/FFT visualizations.

scripts/denoising/FFT.py
  [SPECIAL] Performs 2D Fourier-domain diagnostic analysis and computes image
  metrics related to periodic noise and spatial correlation.

scripts/denoising/FFT_3d.py
  [SPECIAL] Loads 3D OME-Zarr data, selects representative slices, creates RGB
  and FFT visualizations, and computes volume/slice-level frequency diagnostics.

scripts/denoising/patches.py
  [SPECIAL] Creates selected image patches/crops from OME-Zarr data, including
  normalized and raw-scaled channel/RGB representations for comparison or
  training-data inspection.

scripts/denoising/collage.py
  [SPECIAL] Builds fixed-layout collages from available preview images for
  dataset comparison and reporting.

scripts/denoising/normalized.py
  [SPECIAL] Generates normalized views or derivative outputs from selected
  OME-Zarr pyramid levels and records output information.

scripts/denoising/composites.py
  [SPECIAL] Builds channel composites from selected OME-Zarr datasets and pyramid
  levels for visual comparison.

scripts/denoising/create_psf.py
  [RUN] User-facing PSF-generation wrapper. Selects an OME-Zarr image and calls
  psf_creator.py to generate channel-specific PSFs based on image metadata and
  selected optical models.

scripts/denoising/normalizarion_PSF.py
  [RUN] Analyzes, centers, normalizes, and saves PSF TIFF files in a form suitable
  for subsequent deconvolution. The filename contains a historical spelling and
  should not be renamed without updating pyproject and references.

scripts/denoising/PSF_checks.py
  [RUN] Compares PSF TIFF pairs, checks array properties, computes hashes, and
  writes reports for PSF integrity and reproducibility.

scripts/denoising/check_3d_psf_suff.py
  [RUN] Compares 3D OME-Zarr optical/sampling metadata with PSFGenerator
  configuration files and reports whether the PSF configuration contains the
  required and compatible parameters.

scripts/denoising/deconvolve_3d.py
  [RUN] Runs the Fiji/DeconvolutionLab2-based 3D deconvolution implementation on
  selected OME-Zarr datasets and pyramid levels.

scripts/denoising/deconvolve_3d_v2.py
  [RUN] Runs the Python/scikit-image Richardson-Lucy 3D deconvolution path that
  does not require Fiji.

scripts/denoising/compare_deconvolve.py
  [SPECIAL] Compares original and deconvolved OME-Zarr data through selected
  slices, scaling, metadata, and visual/quantitative comparison outputs.

scripts/denoising/n2v_validation.py
  [RUN] Prepares OME-Zarr data for Noise2Void evaluation, applies or compares N2V
  results, supports crop selection, and writes validation outputs.

  [CORE] Interactive parameter-tuning and batch-evaluation workflow for notch

src/PFT/core_prog_parts/denoising/tune_freehand.py
  [CORE] Interactive and batch tuning for freehand FFT masks, rectangular

  [CORE] Builds N2V training data from OME-Zarr, splits patches into training and

src/PFT/core_prog_parts/denoising/n2v_denoising.py
  [CORE] Loads trained N2V models and performs prediction for WGA-DAPI or generic
  2D inputs intended for later segmentation.

src/PFT/core_prog_parts/denoising/psf_creator.py
  [CORE] Reads image sampling/channel metadata, creates PSFGenerator parameter
  files, plans channel-specific PSF jobs, runs PSFGenerator through Java/Fiji,
  and rewrites PSF output metadata when required.

src/PFT/core_prog_parts/denoising/fuji_managment.py
  [CORE] Locates or installs Fiji-related project resources, checks required
  plugins such as PSFGenerator and DeconvolutionLab2, configures Java, and manages
  the local Fiji integration.

src/PFT/core_prog_parts/denoising/Deconvolution_omezarr.py
  [CORE] Fiji/DeconvolutionLab2-based channel-wise 3D deconvolution. Selects PSFs,
  runs restoration, creates output OME-Zarr, and verifies written output.

src/PFT/core_prog_parts/denoising/deconvolution_no_fuji.py
  [CORE] Python/scikit-image Richardson-Lucy 3D deconvolution. Normalizes PSFs,
  prepares image arrays, processes channels, and writes single-scale OME-Zarr
  output without Fiji.

src/PFT/core_prog_parts/denoising/dl2.py
  [CORE] DeconvolutionLab2 command-line support, including channel wavelength/PSF
  selection, OME-Zarr channel loading, validity checks, memory reporting, and
  ImageJ-compatible TIFF stack export.

F. QUANTITATIVE ANALYSIS, STATISTICS, AND GRAPH GENERATION
================================================================================

F1. USER-FACING STATISTICS SCRIPTS
--------------------------------------------------------------------------------

scripts/statistics/__init__.py
  [PACKAGE] Marks the statistics command package.

scripts/statistics/run_pca_mask_terminal.py
  [PRIMARY] Interactive command for PCA-based mask/cell alignment. Selects the
  segmentation method, dataset, samples, and alignment parameters, then calls
  pca_maskt_core.py for standardized cell orientation and output measurements.

scripts/statistics/create_results_graphs.py
  [PRIMARY] Selects a dataset, graph type, and final-values CSV, then calls the
  graph-generation core. Supports profile plots, boxplots, standardized maps,
  colocalization/correlation plots, and 3D-specific outputs.

scripts/statistics/create_results_statistics.py
  [PRIMARY] Selects a dataset, analysis type, test, factors, and CSV, then calls
  the statistics core for AUC, Welch tests, automatic comparisons, or two-way
  ANOVA and writes result tables.

scripts/statistics/create_thesis_graphs.py
  [SPECIAL] Generates the predefined thesis figure set from expected CSV inputs,
  applies a common thesis style, and can collect figures into a combined PDF.

scripts/statistics/intensity_distribution_3d.py
  [RUN] Loads 3D OME-Zarr volumes and metadata, creates channel intensity maps,
  normalized composites, and 3D distribution outputs for quantitative review.

F2. STATISTICS CORE MODULES
--------------------------------------------------------------------------------

src/PFT/core_prog_parts/statistics/__init__.py
  [PACKAGE] Marks quantitative measurement, statistical testing, and graph code.

src/PFT/core_prog_parts/statistics/pca_maskt_core.py
  [CORE] Standardizes segmented cells using PCA orientation, rotation, tight
  cropping, centering, and label handling. Discovers prediction masks, aligns
  2D/3D samples, saves crops and aligned OME-Zarr, and writes per-sample and
  combined final-values CSV files.

src/PFT/core_prog_parts/statistics/results_graphs.py
  [CORE] Loads and normalizes final-values CSV tables and produces publication
  graphs: population/time boxplots, axial and radial profiles, standardized cell
  maps, colocalization/correlation plots, 3D profiles, homogeneity plots, and
  kymographs. Also writes graph summary CSV files.

src/PFT/core_prog_parts/statistics/results_statistics.py
  [CORE] Prepares statistical tables, derives experimental factors, calculates
  AUC, performs Welch t-tests, automatic pairwise tests, Holm correction,
  Cohen's d, and two-way ANOVA, then writes statistical result CSV files.

src/PFT/core_prog_parts/statistics/intenisty.py
  [CORE] Curated intensity-analysis workflow for selected images. Loads planes,
  creates single-channel and RGB outputs, calculates FFT representations, and
  writes intensity-analysis results. Filename spelling is historical and is
  referenced by pyproject console commands.


G. RECOMMENDED MAIN COMMANDS
================================================================================

Run from the repository root with the pft environment active:

1. Validate local project imports:

   python scripts/check_project_imports.py

2. Convert CZI files and validate OME-Zarr:

   python scripts/denoising/process_czi.py

3. Revalidate every existing OME-Zarr in results/img:

   python scripts/denoising/validate_omezarr.py

4. Run the general segmentation launcher:

   python scripts/segmentation/segmentation_launcher.py

5. Run model-specific segmentation commands:

   python scripts/segmentation/run_cellpose_terminal.py
   python scripts/segmentation/run_omnipose_terminal.py
   python scripts/segmentation/run_stardist_terminal.py
   python scripts/segmentation/run_unet_terminal.py
   python scripts/segmentation/run_yolo_terminal.py

6. Train or fine-tune models:

   python scripts/segmentation/train_cellpose_terminal.py
   python scripts/segmentation/train_omnipose_terminal.py
   python scripts/segmentation/train_stardist_terminal.py
   python scripts/segmentation/train_unet_terminal.py
   python scripts/segmentation/train_yolo_terminal.py

7. Standardize segmented cells and calculate final values:

   python scripts/statistics/run_pca_mask_terminal.py

8. Generate graphs and statistical tests:

   python scripts/statistics/create_results_graphs.py
   python scripts/statistics/create_results_statistics.py


H. EXPECTED MAIN OUTPUT LOCATIONS
================================================================================

results/img/
  Imported image data, compact TIFF/PNG previews, OME-Zarr, metadata, detailed
  validation reports, per-dataset validation summaries, and global validation.

results/training_files/
  Optional model-training copies/moves of OME-Zarr data created by the training
  collection script. This directory is not the primary imported-data store.

results/filters/
  Filtered or denoised datasets and related method outputs.

models/segmentation/
  Trained and fine-tuned segmentation models, organized by method, dataset,
  source mode, and run name. Validation reports may be retained inside the
  corresponding model directory.

results/segmentation_predictions/
  Final segmentation masks, integer labels, overlays, per-sample metadata, and
  copied final metrics, organized by method, dataset, source mode, and model.

results/segmentation_screening/
  Pretrained-model baselines, threshold/parameter screens, CSV metrics, JSON
  summaries, HTML reports, comparison images, and optional predicted labels.

results/final_values/
  Quantitative per-cell/per-sample tables used by graph and statistics modules.

results/graphs/
  Generated quantitative figures and graph summary files.

results/statistics/
  Statistical result tables and test summaries.
